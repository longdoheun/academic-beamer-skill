# Build and review

1. Copy the starter into a fresh destination using `scripts/scaffold.py`. Keep dependencies and build products out of the Skill source.
2. Set metadata and replace illustrative content. Keep all real data/plots external to the Skill. Build using `scripts/build.py main.tex --output output --render`. Paths may contain spaces. All shell calls use argv, with shell escape disabled.
3. The builder refuses to publish when TeX fails, the log contains overfull boxes, missing characters, undefined references/citations, or explicit Academic Beamer errors. Underfull boxes and other warnings are reported for review. It copies to a stable final PDF only after automatic checks; the final PDF is still a visual-review candidate, not a certified deliverable.
4. Inspect every PNG at a consistent scale. Check gutters, top baselines, block padding, equations, table rules, plot labels, source-image cropping, Korean/Latin balance and header/footer clearance. Verify that bottom notes stay above the footer, figure notes follow their titles, cover titles start at the intended height, and optional outlines show the intended sections. Check question/result/interpretation as a sequence, not isolated pages.
5. When rerendering, keep the same source/output names. No automatic timestamped PDF copies. Old PNGs with this deck's render prefix are cleared by the builder so a shorter deck cannot leave stale pages; unrelated output files are preserved.
6. Run `scripts/self_test.py --output /temporary/test-folder` after changing the grid or component engine. It tests valid 4/6/8-column layouts, both table families, enlarged block equations, and intentionally failing track totals, invalid settings, row height, equation width and known unreadable figure scaling. When koTeX is available, it measures Korean text inside a block bullet against ordinary body text to verify the intended 0.87/0.90 width ratio. Numerical tests use scaled-point tolerances. Negative tests must fail compilation for the intended reason.
7. When adding or reorganizing designs, also test preset selection, file-based discovery, custom palette/geometry application, vector-asset copying and rejection of unknown/invalid design identifiers. For a structural refactor, compare every rendered PNG with the approved baseline; unchanged hashes preserve the previous visual review, while changed pages require inspection.

The scripts use Python's standard library plus an existing `latexmk` and optional `pdftoppm`. No pip/npm install is needed. If a tool is missing, report that fact; do not silently change the machine.

Build log checks catch some clipping, not arbitrary TikZ absolute-position overlaps or optical mistakes in imported figures. Mark visual review complete only after actually viewing the final renders. The distributed examples are illustrative and cannot validate real research claims.
